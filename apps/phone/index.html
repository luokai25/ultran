Android background access Keep Ultran's approved background work, task alerts and voice updates available when the screen is off. Android and device manufacturers still control scheduling; this does not bypass system security or force-stop controls.

Notifications are optional and used for task updates. Ultran does not need Accessibility access, SMS access, call-log access, or unrestricted file access. Device-specific battery controls remain optional.
Ultran background runtime Installs the official Termux-derived runtime for this device's architecture inside Ultran's private storage. Ultran's agent uses its shell, binaries, libraries and scripts in the background. No terminal screen or separate Termux app is required.

Checking background runtime…

On-device AI model Runs llama.cpp inside the Android app. GGUF weights stay in private app storage and use file-backed memory mapping. This can reduce anonymous RAM use, but it does not guarantee every model will fit. llama.cpp's row-lazy path applies only to tensors marked by a supported architecture, not every transformer layer. Split GGUF models can be imported by selecting every numbered shard together. The context cache still needs RAM, and very large models can be extremely slow on phone storage and CPU. Start with a 1B–3B Q4 model, then test larger ones.
